# WHPU 电费原生查询进度

PR #25 已合并，接通原生选择、余额查询、账号与房间缓存、今日页及只读小组件。当前仅支持已核验的“其他楼栋”分组；另外两个分组保留官方网页。正在准备 rc8，已发布 rc7 仍为网页入口版本。

## 已有实现

- 复用现有校园卡内存会话，电费 Provider 只调用学校当前用户和 `getThirdData` 两个只读接口；不创建支付，不绑定房间，不读取旧郑大缓存。
- 目录按返回的 `code/name/level` 解析，支持不同分组的层级命名；原样保留选项 value，通过表单编码发送，不能把其中的 `&` 当作额外表单字段。
- 金额查询当前仅支持实际核验的收费项目 `182`。目录层级、选择路径与返回房间上下文必须一致，再将官方“当前房间余额为…元”转换为整数分。未核验分组仍需官方页面，不换算电量。
- 查询前后核对校园卡服务账号身份及会话代次；换账号、并发更换会话、HTTP 错误、业务 401、解析错误不产生成功快照。错误文案不包含学校原始响应。
- 复用 Room 的 `kv_cache`，每个账号一个完整快照，内部按收费项目与完整房间路径保存独立余额和时间；刷新失败保留旧结果，成功零余额正常更新。账号指针与快照事务提交，不增加数据库版本，不采用旧电量缓存。

## 额外字段依据

用户授权房间的空调查询中，在浏览器内逐字段比较后确认：选择器的 value 由“编号&名称”组成；campus 对应返回的 area/areaName，building 对应 building/buildingName，floor 对应 floor/floorName，room 对应 room/roomName。只输出匹配布尔值，不记录真实字段值。

同一授权房间使用当前 bearer 头、不携带 Cookie 或额外 Authorization 头重复只读查询，业务返回成功；金额与官方页面一致，返回上下文与请求选择路径一致，未绑定房间。随后在 OPD2407 上完成 Android 学校页面到共享内存会话的交接，原生 OkHttp 目录和授权空调房间余额查询成功；以同一已登录官方页面发起只读查询，在内存比较原生金额与网页响应，金额、人民币单位及房间上下文均一致。未导出真实金额、房间结果或登录凭据。

## 验证

新增 14 项解析和 11 项请求层单元测试通过，失败/错误/跳过均为 0。全部使用人工构造数据，不包含真实房间、金额或凭据。覆盖目录层级差异、表单编码、金额精度与单位、返回错房间/计费项、会话和账号切换、401、HTTP 错误及取消解析。

随后全量 573 项单元测试通过，Debug 与测试 APK 构建成功。专用 API 31 模拟器的 12 项新增 Room 回归通过，覆盖关闭重开、账号/计费项/房间隔离、零余额、失败与取消保留、事务回滚、换号与过期导航拒绝、缓存选择与清理、旧电量数据保护。测试使用独立数据库和人工夹具；模拟器临时切换为 Debug 后，恢复原正式 rc7 准备包，原人工数据库各表及 DataStore 字节一致，系统免打扰状态保留，结束后暂停。实体平板及其学校登录页未改动。

## 原生界面与整合验证

- 复用 Compose 与 AppGraph，逐级选择学校目录；照明、空调独立保存。官方网页登录返回后由用户选择/刷新，支持关闭选择、返回上一层和清除当前账号电费缓存。
- 校园卡与电费在确认账号后，事务切换两个服务的当前账号指针；无匹配缓存时隐藏其他账号快照。今天页与组件读取同一所选房间及时间。小组件按“元”显示余额，未查询时显示“未查询”，不使用旧电量或后台采样。
- 最终功能代码全量 574 项单元测试通过，失败、错误、跳过均为 0；Debug 与测试 APK 构建成功。
- 专用 API 31 模拟器 40 项回归通过：校园卡缓存 13、电费缓存 13、原生电费界面 1、校园服务会话交接 2、网页导航 2、WebView 生命周期 6、组件渲染 3。包含两服务换账号指针联动、浅深色组件人民币显示、失效保留金额和时间。模拟器恢复正式 rc7 发布包，人工数据库全表及 DataStore 字节一致，免打扰状态保留，结束后暂停。

## 剩余边界

本切片已在同一授权房间完成原生照明、空调两项查询；空调原生金额另与同一登录官方页面的只读响应直接比对一致。其他两个分组的余额格式、真实空结果/未绑定错误、自然失效与真实换账号尚未核验，保留官方入口与对应待办，不用人工回归冒充实际验收。实体手机完整视觉与正式包覆盖升级留待发布验收。
