## 第一阶段：稳定性与入口整理

- 移除空教室功能入口及后续调查计划；用户确认没有可用接口渠道且需求较低。旧协议源码不在本轮清理范围。
- 查询登录页始终允许返回原业务；保留学期和缓存，重新登录后由用户刷新。
- 本轮补充主页面加载失败的折叠区外提示和重试，并保持失败页的同步按钮禁用；不把网络错误推断成登录过期，见[登录错误提示](whpu-login-errors.md)。
- 清除网页登录态使用全局 WebView Cookie/存储清理，执行前明确说明会退出应用内所有校园网页，用户确认后清除；不删除 Room 和偏好，不影响外部浏览器。
- 验收自然会话失效、取消登录、真实换账号。免打扰已在专用 API 31 模拟器验证后台边界、进程回收、重启、撤权后备用退出，以及正式 rc10 的实际作息保存与闹钟重排，见[免打扰记录](whpu-dnd-lifecycle-validation.md)；不同厂商的长期后台表现仍需现场观察。

## 第二阶段：网页先可用

- 校园卡、电费经融合门户的“虚拟校园卡”入口进入；复用学校交互登录，不假定教务会话适用。
- 图书馆拆分图书借阅和座位预约。OPAC 当前仅核验 HTTP，使用外部浏览器；不放开应用全局明文流量。
- 超星座位预约使用不含临时 Token 和固定日期的入口，预约、取消、签到由用户在官方页面操作。
- 内置网页提供返回、重试和外部浏览器入口；展示页面错误，不把浏览器登录或页面可达当作 Android 登录与原生接口已完成。

## 第三阶段：查询逐项原生化

顺序：校园卡余额/流水 → 电费房间与人民币余额 → 当前借阅/到期信息。每项先核验认证、请求参数、返回字段、完整分页、错误语义和账号归属；电费另外核验房间及计量单位。

核验通过后复用 AppGraph、Repository、Room 和现有界面；完整成功结果事务落盘，失败保留旧缓存，展示更新时间。新账号/房间隔离。随后接入今日页和只读缓存小组件，不恢复后台电费采样。不推算电量或猜测字段含义。2026-11-16 用户明确确认电费项目 1 的单位为人民币，该组据此使用 `YUAN` 并原样保留数值精度与尾零；官方响应未附单位的观察不变，不把用户确认写成接口自行标注单位，也不将确认扩展至其他收费项目。
