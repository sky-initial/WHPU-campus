# 折叠顶部区域与上课免打扰

## 界面

- 学校登录页的学期选择、同步、换账号和返回教务控制区默认收起为一行，点击展开；展开区域可滚动，学校 WebView 保持独立，不因收起重新创建。
- 登录页复用点选式学年和学期选择器。
- 课表页实践安排默认收起，显示条数；展开后保留全部教师、周次、校区信息，内容较多时可滚动。

## 免打扰

入口为“更多 → 上课免打扰”，默认关闭。用户选择允许闹钟，并沿用系统优先通知设置。启用前由用户在系统设置中授予免打扰访问、精确闹钟权限。

仅使用当前学期的 `whpu` 课程、已确认的第一周日期和现有 WHPU 作息；演示、其他学校来源、自定义日程和没有具体起止时间的实践安排不触发。单双周按缓存记录的周次计算，日期明确的排课优先使用日期；采用 `Asia/Shanghai` 时区。一次排课内的小课间保持免打扰，不同课程间的空档结束免打扰；相交或衔接的时段合并。

使用独立 `AutomaticZenRule`，通过 `setAutomaticZenRuleState` 更新本应用规则，不调用全局 `setInterruptionFilter`。下课、关闭功能或课表清空时只结束自己的规则，不强制关闭用户的其他勿扰模式；系统中手动关闭或删除该规则后，后台不自行重新创建。

下一次上下课边界通过 `setExactAndAllowWhileIdle` 调度，并保留一个非精确备用调度，用于精确闹钟权限之后被撤销时补做清理。备用调度可能受系统节电延迟，不承诺撤销权限后准点切换。应用启动/恢复、开机、覆盖更新、时间/时区变化、课表与第一周设置变化时重算计划。权限不足时暂停，授权后由用户重新开启。

设备强行停止应用会中断后台切换，厂商后台限制也可能造成延迟。页面提示允许后台运行，并提供系统优先通知设置入口。应用配置和系统规则 ID 不参与云备份或设备迁移，避免换机后自动启用。

实现依据：[Android 自动免打扰规则](https://developer.android.com/reference/android/app/AutomaticZenRule)、[更新规则条件](https://developer.android.com/reference/android/app/NotificationManager#setAutomaticZenRuleState(java.lang.String,%20android.service.notification.Condition))、[精确闹钟与权限](https://developer.android.com/develop/background-work/services/alarms)。

## 测试

纯计算用例覆盖上下课边界、北京时间、单双周、重叠与衔接课程、空档、日期优先、来源与学期隔离、无确认日期、无效时间及调整第一周。

系统回归用例需要用户先授予权限。使用人工时段、单独的临时 DataStore 和独立测试闹钟编号，检查规则进入/结束、允许闹钟、保留其他活动规则、关闭清理，以及系统删除规则后不重建；不写入真实课表和用户的免打扰偏好。测试结束移除测试规则和临时文件。

后台真实上下课触发、重启以及不同厂商节电策略的长期表现仍需持续验收，不以纯计算测试替代。

自动化结果：469 项单元测试、57 项设备测试全部通过（失败、错误、跳过均为 0）。其中 3 项系统免打扰用例在用户授予权限后实测规则开启/结束、保留其他活动规则、删除后不重建；其余 54 项为现有 Room 回归。Debug 应用与测试 APK 构建成功，设备为 OPD2407 / Android 16，覆盖安装保留用户数据。

界面验收：实践区默认只显示标题，展开可见原有 3 项安排，收起后详情隐藏；登录页展开/收起后 WebView 高度分别为 974/1612 像素（本次平板横屏），收起后恢复原高度。免打扰测试前后系统模式保持一致，临时规则已清理，用户授予的权限保留，应用功能开关保持关闭。实际上下课的后台触发尚需在真实时间边界持续验证。
