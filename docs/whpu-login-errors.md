# 教务页面加载失败提示

2026-11-15 用户反馈教务系统普遍无法进入，并明确不是仅应用内失败。具体原因未知；网络攻防演练只是用户提出的可能原因，未作为已核实结论。此次没有访问教务服务。

## 独立发现的客户端问题

学校登录页的操作区默认折叠，原网络及 HTTP 错误提示位于操作区内，因此失败原因也被收起。主文档错误后 `onPageFinished` 仍可能依据域名启用课表同步。该控制流问题独立于学校服务可用性。

加载错误现在在折叠区外显示，并提供“重试”。同一次导航失败后保持同步禁用；主动重试或新的允许跳转清除旧错误，成功完成后恢复同步。子资源错误不阻断已成功的主页面；成绩、考试登录页返回操作始终可用。

API 31 的人工主文档 503 实测回调顺序为 `onReceivedHttpError → onPageStarted → onPageFinished`。首次实现直接在 `onPageStarted` 清错，导致 503 用例失败；现按失败页面 URL 保留同一次加载的错误，不让迟到的开始回调抹掉提示。

重试加载正式教务 HTTPS 入口，保留 Cookie、内存会话及离线缓存，不自动提交同步，不要求用户重新输入密码，也不推断失败是会话过期。

## 验证范围

新增人工 WebView 回归覆盖主文档 503 后重试成功、主文档网络错误下返回业务页，以及子资源 503 不影响同步。所有请求由本地响应拦截；网络失败通过人工响应流读取失败触发。它们验证应用的提示和按钮状态，不代表学校已恢复或真实重登录已验收。
