# 电费入口与校园卡组件回归

## 问题与改动

WHPU 电费原生查询尚未核验接入，但原小组件取数仍读取郑大房间配置、读数和采样，可能展示不属于 WHPU 的旧缓存。现改为只读取当前 WHPU 账号和所选卡快照；左侧明确显示“电费查询 · 待接入”和“官方网页 · 打开”，点击仍进入现有官方网页入口。不显示照明/空调、电量单位或可用天数，不修改旧协议类和数据库。

校园卡余额、今日/本周消费和笔数保留，更新时间仅取校园卡缓存，按北京时间显示，与原生查询页一致。启动器预览复用正式组件布局，避免两套布局的消费提示排版不一致；静态 PNG 同步标注示例数据和电费接入状态。

## 本切片验证

- 28 项 WidgetBalance 单元测试通过，失败/错误/跳过均为 0。新增覆盖旧电量/房间/采样不展示、时间只取校园卡、无缓存提示、生产快照映射及设备时区不同的北京时间显示。
- API 31 专用模拟器 2 项设备渲染测试通过：250dp / 340dp 宽度、深浅色，状态文字宽高可容纳；校园卡值仍显示。布局预览显式标注示例且不宣称已有电量查询。
- 静态 PNG 从人工数据预览布局实际渲染导出并目视检查，不含真实金额或身份。
- API 31 启动器实际放置通过：左侧状态与人工校园卡缓存可见，右半点击进入原生校园卡缓存页，左半点击进入“宿舍电费”官方页面容器。模拟器保持离线，该项仅验证路由，不作为学校电费查询成功的证据。
- Debug 和设备测试 APK 构建成功。此分支基于已合并 main，独立于尚未合并的免打扰 PR #19；未覆盖实体平板上的 PR #19 测试版。
- 没有变更 Room schema、签名、版本号或学校请求。模拟器测试后暂停，平板网络和临时亮屏设置已恢复。

实体平板的实际放置、点击、缓存一致性及断网冷启动结果在[校园卡证据记录](whpu-campus-card-evidence.md#实体平板组件与离线冷启动补验)。这些在本切片之前的 PR #19 构建上完成，不作为本切片修改后实机显示已验收的声明。

## 电费入口最新边界

用户确认今日校园内浏览器已能进入房间查询页。平板 WHPU 的门户前两个电费分组仍跳到学校 `/plat-pc/notfound`，第一个分组临时切换移动端显示也相同，测试后已还原。尚缺可用分组/入口及房间查询响应证据，不据此猜测认证、金额单位或电量，也不把旧 404 作为学校整体不可用的结论。
