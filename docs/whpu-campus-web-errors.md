# 校园网页主页面错误与导航回归

## 问题与修复

在 API 31 专用模拟器中用本地 HTML 和 HTTP 503 响应复现：校园网页的回调顺序为 `onReceivedHttpError → onPageStarted → onPageFinished`。旧实现会在开始回调中清除刚收到的错误，随后把失败的校园卡页面标为可以交接登录态。基线三个设备用例中该用例失败，子资源错误及 Activity 退出清理通过。

现在保留失败主文档的地址标记，使同一文档的开始回调不会清除错误；网络、HTTP 或证书错误发生时取消交接就绪状态。用户重试、返回入口、后退或正常导航时开始新一轮加载，成功后恢复正常交接。仅主文档 HTTP 错误影响整页状态，图片等子资源失败不禁用正常页面。

地址标记只在当前 ViewModel 内存中使用，不写入保存状态、偏好或日志；错误文案只显示状态码或已有通用提示。本切片不改变接口请求、缓存、Cookie 清理、允许域名或数据库结构。

## 验收方式

`CampusServicePageErrorTest` 在 WebView 首次布局前安装本地请求拦截，所有主文档和子资源都返回人工响应，不访问学校。覆盖：

- 主页面 503 保留提示并禁止交接，成功重试后恢复。
- 失败后返回上一页或正式入口，清除旧错误。
- 带 query 和 fragment 的主页面失败与重试。
- 子资源 503 不阻断成功页面。
- 实际点击页内 fragment 链接后返回，不重载主文档，交接保持可用。
- 关闭 Activity 后真实 ViewModel 清理、WebView 脱离，拒绝延迟交接。

页内导航初版测试通过脚本修改 `location.hash`，后退未返回预期文档；该样本未归因为产品故障。测试改为真实触摸链接，并记录人工入口回调、当前 URL、交接状态及所有主文档请求数，再核对用户点击对应路径。
