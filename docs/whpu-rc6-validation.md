# rc6 发布与验收

版本 `0.34.0-rc6`，`versionCode=105`；准备基线为 PR #19 / #20 合入后的 main `5223298`，最终发布基于 PR #21 合入后的 main `9c3e11d7b9e59bc5dd02f0bcdceeaa478da5b084`，保持 Room v10、正式签名和现有工具链。[已发布候选版](https://github.com/sky-initial/WHPU-campus/releases/tag/v0.34.0-rc6)。

## 合并主分支验证

- main `5223298` 全量 547 项单元测试通过，失败/错误/跳过均为 0；Debug 和测试 APK 构建成功。
- OPD2407 / Android 16 覆盖安装前后，应用数据库和 DataStore 文件在内存中逐字节比对一致，仅记录布尔结果，未导出真实记录；没有卸载应用。
- 同一平板通过 7 项隔离免打扰规则测试及 2 项组件渲染测试，共 9 项。测试前系统处于优先免打扰；只读检查当前配置为 Android 的 ScheduleConditionProvider 定时规则生效，没有 WHPU 自动规则，测试结束保持原模式。没有将历史规则日志当作当前规则。
- 实际平板界面显示系统免打扰开启，并在应用开关关闭时提示检查其他生效来源。要求系统关闭的界面用例未在此状态下运行，没有为测试关闭系统定时规则。
- API 31 人工数据模拟器通过相同 7 项规则、2 项渲染及 1 项状态界面用例，共 10 项。结束后恢复测试前的权限/免打扰状态并暂停模拟器。

这说明当前平板的系统定时规则被保留，不证明 Reno 11 Pro 的故障原因。该手机尚未连接且没有生效规则证据，继续保留待定位。

## 候选包与升级

- 候选版全量 547 项单元测试通过，失败/错误/跳过均为 0；R8 正式 Release 构建与发布检查通过。
- 签名与已发布 rc5 一致，版本代码 105、名称 0.34.0-rc6，未启用 debuggable。
- 专用 API 31 模拟器使用人工数据，正式签名 rc5 → rc6 通过 `install -r` 覆盖升级。升级前后全部数据库表记录一致，DataStore 文件集合和字节完全一致；非空学习记录与标签保留，累计 25 分钟可见，原生校园卡人工余额与账单可读，免打扰状态页可读。
- 为准备签名环境，先备份该模拟器的人工数据库和 DataStore，再由 Debug 切换至正式 rc5 并恢复人工夹具；没有复制加密凭据偏好，也没有卸载实体平板。先确认旧 rc5 能读取数据，再开始实际 rc5 → rc6 覆盖验证。结束后暂停模拟器。

以上为准备阶段验证。合并后的最终发布另行完成以下检查，不以准备包代替主线产物。

## 发布版显示补验

在 API 31 专用模拟器的最终正式 rc6 上，使用人工校园卡、成绩与考试缓存，保持离线。字体缩放设为 2.0；手机为 1080×2280 / 440 dpi，平板横向尺寸为 1600×1000 / 200 dpi。

- 深色及浅色的平板尺寸下，校园卡、成绩、考试和免打扰页面文字可读；免打扰下方权限与系统设置入口可滚动到达。
- 手机尺寸下校园卡、成绩和考试的深浅色页面可读；按钮及卡片选择换行，学分、绩点和学分绩点仍显示。浅色免打扰页底部入口可滚动到达。
- 人工双卡切换后，改变显示尺寸及后台返回仍保留选卡；检查结束恢复原选卡。此项只证明人工缓存的选择记忆，不代表真实双卡认证通过。
- 首次从平板尺寸切回手机尺寸时，截图出现全黑及旧尺寸残留，未计为通过；恢复固定手机尺寸并重新启动应用后，重新采集的浅色页面正常。尺寸切换瞬间的表现仍待进一步定位，不据此声称所有配置切换已通过。
- 后续对照复测：默认字号深色下，应用成绩页与 Android 系统设置页分别从 1600×1000 / 200 dpi 重置为 1080×2280 / 440 dpi，重置后两次采样的页面边界均恢复正确，没有黑屏。再按浅色、两倍字体重复尺寸切换，校园卡、成绩、考试和免打扰四页均恢复正确边界，成绩和免打扰截图复核正常。两轮未复现首次异常，尚不足以确定其来源；未据此添加应用修复。
- 显示检查没有修改生产代码。恢复原字号、显示尺寸、旋转设置和跟随系统主题后暂停模拟器。

这是模拟器尺寸与人工数据验证，不替代实体手机/平板的完整横屏、系统字体及现场免打扰验收。

## 仍需现场条件

电费在今日校园内可用，但 WHPU 的对应可用入口、认证和查询字段尚待核验；图书借阅尚未完成独立登录与验证码。真实多账号/多卡/未绑定、学校自然失效后的完整重登录及手机免打扰故障仍需实际条件。预约、续借和缴费均由用户在官方页面执行。
