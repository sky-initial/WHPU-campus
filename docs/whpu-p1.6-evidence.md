## 认证证据及边界

- 初始入口展示教务用户名和密码表单；表单 action 指向同域 `/xtgl/login_slogin.html`，method 为 POST。
- 表单含 `yhm`、`mm`、`csrftoken`、`language`、`ydType` 等字段。本次只检查字段名，不记录字段值。
- 页面引用 RSA 相关脚本及 `/js/globalweb/login/login.js`。仅凭脚本依赖不能确定完整加密、提交和失败处理流程。
- 登录由用户手动完成。本轮未捕获该次登录的请求、响应或跳转链，不能证明绕过 CAS，也不能证明必须经过 CAS。
- 独立 HTTP 客户端读取公开登录页及 login.js 返回 HTTP 403；响应 `Server: rump/d`，HTML 标题为“waf拦截”。加上常规浏览器 User-Agent 和 Referer 后读取脚本仍返回同类响应。
- 同时，用户已登录的浏览器可以查看课表并读取课表 JSON。这说明两种客户端存在访问行为差异，尚未定位差异原因。
- 未关闭证书校验、未绕过学校防护、未反复提交账号密码、未导出浏览器会话。

## 交互登录与导入实现

已新增“学校登录与课表同步”入口，复用 WebView 展示学校原始页面。导航只允许已确认的 `jwglxt.whpu.edu.cn`、`cas.whpu.edu.cn` 和 `sec.whpu.edu.cn` 的 HTTPS 443 页面，不添加密码输入框或 JavaScript 桥，不忽略证书错误。学校页面负责密码、验证码与 MFA。用户登录后点击“同步到课表”；课表保存成功后弹出日期滚轮，确认后进入课表。

OPD2407 设备联调发现：原先仅允许教务和 CAS 域名，导致学校页面跳转到 `https://sec.whpu.edu.cn:443` 时被客户端拦截，停留在 CAS 登录页且同步按钮不可用。定位版本只展示跳转的协议、域名和端口，不展示 URL 路径、查询参数、密码或票据；重新打开登录入口即复现该目标，已据此补充精确域名。新增“返回教务”入口，不清除 Cookie。

补充 sec 域名后，设备再次反馈停留登录页；本次状态提示明确显示学校返回 `http://jwglxt.whpu.edu.cn:80`。客户端现将这个域名及端口的顶层 GET 跳转升级为 HTTPS 443，保留编码后的路径和查询参数。仍禁止明文请求，不重放 POST，不将该规则扩展到其他域名或端口；不将真实票据写入应用提示或日志。该修复安装后，用户确认成功导入。

用户点击同步时，通过 Android CookieManager 读取课表端点适用的 Cookie，限定给教务域名的 `/kbcx` 请求，内存中使用 WebView 的 User-Agent 发起原 POST 请求。该机制的 API 依据为 [Android CookieManager 文档](https://developer.android.com/reference/android/webkit/CookieManager)；本次真实账户已由用户确认导入成功。浏览器组件处理方式参考 [Android WebView 文档](https://developer.android.com/develop/ui/views/layout/webapps/webview)。

导入前不填写日期。首次导入可在没有日期的情况下保存完整课表；导入成功后用年／月／日滚轮选择第一周周一，按学期保存。重新导入的滚轮优先显示已有日期，后续课表设置也使用同一滚轮。若设置前退出，缓存保留，重新进入课表时继续提示设置。用户本次确认的日期为北京时间 2026-09-07，仅作为本轮验证输入，不作为应用默认日期。今日页与课表使用北京时间，学期日期标为用户设置。滚轮使用 Android [NumberPicker](https://developer.android.com/reference/android/widget/NumberPicker)，文字颜色随应用主题调整。

用户提供的作息图对应 11 节：08:00–08:45、08:55–09:40、10:10–10:55、11:10–11:55、14:00–14:45、14:55–15:40、16:00–16:45、16:55–17:40、18:15–19:00、19:10–19:55、20:05–20:50。此表用于 WHPU 真实课表，与演示作息分开；来源是用户提供的截图，并非本轮从学校接口查询。

完整响应解析后，在同一 Room 事务内保存课程、实践安排、同步记录和学期信息，最后设为当前学期；首次日期尚未设置时保持为空，日期在导入后的用户设置中另行保存。同账号刷新保留其他学期，确认换账号后的替换规则见下文。保留演示缓存和自定义日程。同步失败保留现有快照。“清除登录态 / 换账号”清除应用 WebView Cookie、WebStorage 和内存会话，保留离线课表；它不宣称完成学校服务端全局退出。

深色模式修复：课表色块跟随应用内的深浅色设置，半透明卡片显式使用主题文字色，主题根节点提供正确的默认文字色。

课程教师显示：点开课表中的某次排课时，详情只使用该次排课的教师；课程总览和从总览进入的详情使用本周排课的教师，不再汇总全学期名单。本周有不同教师分次授课时，总览保留本周涉及的教师，点入具体排课时只显示对应教师；本周无课时不回退到全学期名单。按用户补充要求，实践安排继续展示全部教师。

## 本轮验证结果

### 2026-11-08 登录与同步稳定性

- 在已登录的学校课表响应中核对了结构：`xsxx` 为对象，`XH_ID` 为非空字符串；只记录字段名和类型，不将字段值写入文档或测试样本。
- 导入读取 `xsxx.XH_ID`，在应用私有 Room 数据库中保存当前缓存的账号归属，账号标识对象的诊断字符串不输出字段值。未新增数据库表或更改数据库版本。
- 同账号刷新保留其他学期。不同账号或尚无归属标记的旧版缓存需要用户确认；确认后重新请求，取得完整响应后在一个事务中替换旧账号所有已登记真实学期的学校排课、课程、实践安排、同步记录和课程显示修改，再写入新账号归属。演示数据与设备上的自定义日程保留，学期日期设置保留。
- 取消确认、缺少账号标识、请求失败或事务失败均不替换旧快照。事务末尾校验会话，校验失败回滚已经执行的数据库写入。
- 生产同步改为可取消的 OkHttp 异步请求；点击取消、离开导入页或学校页面开始导航时取消请求。每次请求使用独立 Cookie 快照，旧响应不能把 Cookie 写回新登录会话；保存前校验会话版本及协程状态。
- 收到会话失效响应时只清除对应版本的内存会话，保留离线课表。已知 WAF 拦截页、登录表单 HTML、一般 HTML 和 HTTP 错误分别处理；这些分类的异常路径通过人工响应验证，未宣称已观察学校自然会话过期的全部行为。

- `:app:connectedDebugAndroidTest`：OPD2407 / Android 16 上 22 项通过。新增用例覆盖归属重开持久化、同账号跨学期保留、异账号确认、跨学期原子替换、账号写入失败回滚、会话变化回滚、旧缓存首次绑定和缺失身份拒绝。测试使用独立临时数据库及人工账号。
